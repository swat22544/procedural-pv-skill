# 歌词参与分镜与叙事

> 公开版阅读约定：`<…>` 是待配置的路径占位符；文中原项目文件名属于所指参考仓库或本地案例，不表示随本 skill 附送。原研究的抽样与运行记录仅说明当时的验证范围，不代表你的环境已经通过。跨机器使用先读 [环境接入](environment-setup.md)。

从 pdoom 与 Nyankomintsu V4 提炼。来源逐例见 [pdoom 歌词案例](pdoom-lyric-cases.md)、[Nyanko 歌词案例](nyanko-lyric-cases.md)。这里是迁移方法，不是要求新歌复用科技题材、橙色、聊天窗或固定字体。排版实现另见 [rendering-techniques.md](rendering-techniques.md)，镜头连续性与对象接力沿用已有参考。

## 1. 先决定歌词在这镜里做什么

不要先把整首词排到底部，再给每句寻找入场特效。逐句判断以下角色，可在同一镜中交接，但同一阅读时刻先指定一个主载体：

| 角色 | 观众为何在此处读它 | 动作必须有的结果 |
|---|---|---|
| 讲述/稳定阅读层 | 补充正在看的动作，或复杂运动时保护理解 | 读完并明确交给下一句 |
| 角色发言/消息 | 角色说出、发送或留下这句话 | 对方反应、未回复、状态标记、历史记录或被删除 |
| 场景中的文字 | 纸张、路标、图表、建筑、轨道具有容纳文字的功能 | 文字跟随所属物体的空间/材质规则 |
| 被操作的对象 | 歌词被书写、盖章、遮挡、点燃、改写或执行 | 操作留下可见终态，不能只是临时闪光 |
| 独立文字镜头 | 这一词或句本身就是当前最重要的画面 | 构图、节奏和出口完整，承担下一镜的起因 |

“嵌入”不等于必须三维化。pdoom 有固定在屏幕上的主词、沿世界投影定位的题字、逐字近似透视和真实3D字板；Nyanko 也大量使用平面阅读带。选最小够用的空间关系。

先写一句导演说明：**谁以什么身份说出什么意图，文字成为哪种可见行为，观众看完后多知道了什么。** 如果只写“字幕飞入”“文字很酷”，叙事设计还没有完成。

## 2. 共用主题语法，而非只共用颜色

为这部片建立四类约定：

1. **声音身份**：谁用什么字体、颜色、大小和句法。Nyanko 的 serif/橙是 AI、sans/奶油是用户、mono 是系统；这是该片的语义编码，不是通用字体配方。身份改换时要有事件依据。
2. **场景载体**：工程图用尺寸/坐标/线框，公文用字段/章/批注，版画用纸边/墨色/剪影，聊天用发送与回执。歌词沿该载体的组织方式排版，而不是在仿真背景上悬一条无关字幕。
3. **动词语法**：描线对应书写，烧过对应消耗，盖章对应裁定，光标对应操作，遮词对应未知。动效要改变可读内容或环境状态。
4. **层级**：主唱词、关键词、角色回复、系统标签、背景纹理分别标记。装饰代码、概率、图注不冒充唱词；大字提炼不自动等于完整歌词覆盖。

建立 `textRole` 表。每个文本节点注明 `lyric / lyric-emphasis / dialogue / system / annotation / texture`、说话者和来源。Nyanko 的伸手字符流是硬编码程序文本，唱词另在纸条显示；pdoom 的辅助刻度与候选概率也不能计入歌词。

## 3. 歌词分镜卡

```text
shot_id / source_line_id / occurrence_id:
说话者、对象、此句意图:
叙事前态 → 歌词动作 → 可见后果:
主载体及主题依据:
完整唱词在哪里读；强调词在哪里；哪些是辅助文本:
布局: 基线/对齐锚点/行宽/层级/负空间/预留长度
依附: screen / world-anchor / affine-glyphs / curve / real-3d
遮挡与后期责任: 谁可以挡字，谁必须避开字，何时恢复清晰
时钟: song / line / word / syllable / beat / visual interpolation
首次可读 → 动作推进 → 全文完成 → 稳定读窗 → 退场:
镜头: 跟随什么、何时停、读窗内还动哪些参数
出口: 字/路径/纸面/光标/消息状态交给下一镜的什么
证据: 源码函数、歌曲时间、前中后帧、连续窗口、听校状态
```

短重复句可共享卡的规则，但 occurrence_id、结果和出镜状态单独记录。翻译/注释是额外阅读负担；不能不经规划再把一整层双语压上来。

## 4. 把一句话拆成可读的动作阶段

顺序不是强制模板，而是检查遗漏的工具：

1. **预备**：载体先出现、位置建立，或沿上一镜遗物进入。可以显示低对比未唱词，但不要无理由提前泄露关键结论。
2. **触发**：跟唱点亮、落笔、发送、揭词或物体响应。唱词跟人声，镜头切点可跟节拍；两者不必同一时刻。
3. **推进**：一个明确机制持续工作。用同一进度驱动文字与动作，例如 `word progress → burn distance → spark position + char state`。
4. **完成与阅读**：让观众看见完整句和动作结果。检查最后一个词、最晚错峰元素，不只检查中间词。相机可停追踪、减速、改为轻推；不要求绝对静止。
5. **交接**：文字保留为记忆/物件，或消耗成下一镜材料，或退出并把阅读位置交给下一句。不要无依据回到初始空白。

全文显示时长与“真正可读”的时长不同。文字虽已生成，若仍在边缘、遮挡、背向、失焦、倾斜压缩或转场混合中，就不能全算读窗。

可定义 `readable(t)`：必要字形在画内、尺寸/对比达本项目阈值、遮挡允许、运动可追踪。记录 `completeAt` 之后满足条件的区间，实际看最终尺寸视频再判断。不要宣称一个固定毫秒值适合所有语言、字数和镜头。

## 5. 构图先把完整文字放稳

- 先用完整句和最终字体定行宽、换行与锚点，再裁出当前显示部分。居中句不按每帧短前缀重新居中；消息可有设计过的生长，但相邻布局要可预测。
- 前缀、高亮、描边、擦显、光标和粒子采样尽量共用整行/字形布局；先确定 kerning、tracking、baseline，再分色。切片分别测宽容易丢切点两侧字偶距。
- 动态字号/字宽是镜头构图参数。pdoom 的 Archivo 是离散字体实例选择，并非任意连续字体轴插值。转折时换宽/换重量要预排最终占位。
- 阅读路径与动作路径相容。沿圆/曲线阅读时逐字按切线转，长句需要弧长分布、最大弯曲与压缩判断；不是把一个长矩形无限弯折。
- 三维并不免除排版：先定可读机位、倾角、近裁面、遮挡和前景层级，再选择纹理字板、字形几何或屏幕锚定。关闭深度测试的字板不能称为真实实体遮挡。
- 屏幕固定唱词可以与运动背景同主题。以稳定基线、同一纸墨/字体语法、时间事件和周边物体关系建立融景，不必每字都追摄像机旋转。

中文等复杂文本迁移时按字素簇/字形 shaping 处理，而非直接照搬英文 `string.length`、空格分词或逐字符 kerning 逻辑。此两库英文实现不等于通用多语排版引擎。

## 6. 选与语义有关的揭示方式

| 方式 | 适合的叙事动作 | 要守住的联系 |
|---|---|---|
| 消息打字 | 说话、犹豫、生成、等待 | 发送者、输入速度、完成后停留、对方反应 |
| 逐词/音节擦显 | 人声持续推进一句话 | 高亮不改变字形位置；空隙/长音保持正确进度 |
| 单线书写 | 签名、承诺、记录、手工推演 | 笔尖与累计线长同源；不是字形轮廓描边冒充手写 |
| 圆弧/曲线字 | 几何关系、路径、导线、引力 | 同一路径的采样、弧长、切线、阅读顺序 |
| 变为字段/章/纸条 | 审核、命名、规则、证据 | 字段与判断有因果关系，章的到达有明确落点 |
| 遮罩揭词/移除词 | 未知、恢复、删除、拒绝 | 遮罩先前覆盖的内容与后来揭示/删除的内容相对应 |
| 大字独镜 | 宣言、重点、冲击、节拍落点 | 词内层级、留白、可读阶段、进入与退出都被编排 |
| 字成为物质 | 消耗、破裂、归档、坠落、堆叠 | 来源字可识别，粒子有去向，必要唱词另有阅读保障 |

不是每个词都应同时弹跳、转动和发光。一个主变化承担句意，其余参数配合；高强度效果放在语义峰值或转折，而不是整段恒定开满。

## 7. 歌词与镜头互相让出任务

使用 [pdoom 镜头细则](pdoom-camera-method.md) 的观察任务与跟随/释放规则：

- 讲清关系时先给能读的机位；接着倾斜/拉远揭示字属于怎样的世界。
- 字的动作很快时镜头可以稳定；镜头快速换位时字可先以轮廓/形状建立，再在落点完成阅读。
- 跟随燃点、路径头或正在唱的楼层，读完后放行，让过去的词留在世界里。不要无论新旧词都永远锁中心。
- 对局部动作推近前，验证最后一个长词不会在镜头边缘截掉；退远展示结构前，先给核心句清晰阶段。
- 主体图像与歌词有时轮流主导：Nyanko 的几何与对话、内心版画与现实消息可以交替，不必每帧都摆同样比例的字与角色。

## 8. 让字幕成为完整分镜

独镜必须有起因、内部推进和出口。可用以下结构而不是仅把字号调大：

- **过程镜**：一词/一组词随步骤累积，最终输出/失败成为下一镜原因。
- **尺度镜**：小型词进入巨大结构，镜头拉远才说明它是什么的一部分。
- **材料镜**：句子已在纸/绳/图层中，动作消耗或改写它，材料连续转入下一场。
- **主观镜**：现实消息在关键词处进入人物内心版画；回到原对话时按整段歌曲时间继续，不能重放刚才的发送。
- **复唱镜**：复用字形、构图或道具，但更改操作者、权限、回复、损伤、持有关系或结果，让观众读出成长/失控。

Nyanko 的 `withInserts` 把底层镜头的 whole-clock 传回插入后的各片段，这是“离开又回来”的具体实现。照抄视觉而重置局部 `u.since` 会造成消息/相机回退。相关原则亦适用 [Misaka 接力方法](misaka-motion-method.md)。

## 9. 时间与文本数据要可追查

- pdoom 的 word/syllable 数据能驱动连续歌唱进度；Nyanko 的导入结果主要是行时间，`typed` 用字符容量和行长比例安排显示，部分重点动作另读 cue。
- 不把消息显示结束称为最后音节结束。Nyanko 的26 chars/s 与60%上限只是一片的打字规则；多种 cue 来源共存，不能泛称全片实测逐词对齐。
- 单独记录 `source_line`、`occurrence`、`display_text`、`word_map`、`emphasis_ranges` 和非歌词文本。大小写/排版标点规范化与实际词变更分开报告。
- 缺行、重复副歌、重新分行、英文缩写点号都可能影响匹配。先验证词序，再用原字体检查版面；填充工具接受了数据不等于音画已校准。
- 歌曲时间与发布片头分开。此 Nyanko 快照有5秒前滚，源码时间加5才是完整导出时间；研究抽帧使用歌曲时间，不把5秒写进全部 cue。

## 10. 验收要能回答的问题

1. 去掉背景后是否还能辨认主唱词？恢复背景后文字是否属于这个场景？两项都要看。
2. 在入点、唱点、全文完成、动作结束和出点，谁拥有文字、谁在绘制？是否双份/漏行/闪回？
3. 完整词有没有在画外、被遮、镜像、压扁、缩得太小或只在一帧出现？高亮是否与底字重合？
4. 文字所描述的动作是否在画面产生后果？删除是否减少历史、盖章是否结束裁定、重复执行是否改变计数/错误？
5. 插镜后、复唱时、重进场景时，有没有正确延续状态与时间？
6. 页面资源/字体/场景是否真加载，还是引擎捕获异常后画 fallback？检查 console、场景 ID、缺资源与错误占位。
7. 用最终导出编码的连续片段复看；字幕调度与像素确定性不能替代音频听校。静帧不足以证明读窗、动作速度和切换成立。

研究只复现必要窗口，不自动重渲整片或发布素材。保留代码、歌词、字体、角色素材各自许可。下次生产读取此方法与对应案例后，先做包含“入场—动作—读完—交接”的短镜头，再扩展全片。
