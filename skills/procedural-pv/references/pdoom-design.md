## 1. 核心导演方法：镜头随“理解发生变化”

它的画面变化由“观众需要理解的新信息”驱动。二维图表先交代关系；曲线发生坠落时，镜头跟着信号离开图表平面；随后斜视地形揭示深度，再用低机位、俯视和滚转改变观众对同一结构的理解。对象、观察位置、文字姿态与音乐共同推进。

不要把这归纳为“多加旋转/缩放”。相机位置决定透视关系，平移会改变视差与遮挡；在同一位置改变焦距/FOV，改变的是视野和画面尺度。推进并调整焦距以保持主体大小时，背景与主体的尺度关系才随位置改变。全屏缩放是二维画面操作。镜头位置与注视目标可以不同步，形成先看到动作再被带入动作的迟滞。滚转改变参考系，应有事件理由。

可复用的镜头记录：

```text
id / section / lyric-or-music anchor
purpose: 这时要看见哪个动作或关系
subject: 主体及稳定 ID
view: 景别、方位、俯仰、透视/平面
camera: position(t), target(t), fov-or-focal(t), roll(t)
timing: 预备、启动、峰值、刹停、阅读保持
text: 世界空间/平面/稳定字幕，阅读窗口
exit: 交给下一镜的对象、轮廓、位置、速度、颜色
cut: hard / snap-reframe / match / portal / morph / overlap
qa: 入点、落点、出点、切点两侧与连续预览
```

这是设计记录格式，不要求每个镜头写冗余字段。相机分段函数应从事件表派生；不能把旧歌秒数复制进新歌。

## 2. 机位编排：一场景内也有剪辑

### loss：平面 → 坠落 → 峡谷 → 权力翻转

实现：`app/src/scenes/loss.ts:chartCam / landCam / camera / rollAngle`（约 520–591 行）。

- 先窄视场、接近平面的图表视角，主体可读。
- 曲线骤降时，position 与 target 使用不同进度；target 先追随 spark，再接到地形落点。相机从图表位置降到三维地形，FOV 只小幅改变，避免靠极端变焦代替空间运动。
- 到达后从高斜角绕到峡谷侧面，再有意切到更低、更近的观察位置；对象仍是那条曲线和同一信号。
- 末段俯向盆地，roll 在约 0.45 秒内转过 π，再有少量余转；与此同时缩短距离、扩大 FOV，向最低点俯冲。意义翻转由观察系真正翻转承担。
- 代码还有相机离地高度约束，不能只抄漂亮坐标而忽略穿地。

**迁移**：为“发现、下坠、反转、深入”安排明确的观察关系。先确定可读的开场画面和到达画面，再生成中间路径；不要求所有参数同时套一条 ease。

### room：短句内的多机位与短促追拍

实现：`app/src/scenes/room.ts:buildShots / orbitKey / keyAt / camAt`（约 644–764 行）。

| 顺序 | 视角与动作 | 作用 |
|---|---|---|
| 入场 | 从门后被带入，倾斜画面逐渐摆正 | 让冲击成为相机入场原因 |
| 右侧通道 | 侧移后沿过道前进，书架从前景掠过 | 用近远视差表现速度和封闭空间 |
| 左侧低机位 | 低处仰看标牌与出纸口 | 改变规模感，同时看清装置开始工作 |
| 标牌近景 | 正对文字迅速推近，在重拍落定 | 给关键词一个读清的落点 |
| 桌面高机位 | 上提后绕桌，加速并逐步滚转 | 展示作用范围扩大与感知失稳 |

这里多处换机位是约 0.09–0.16 秒的 outExpo 短过渡，不全是硬切，也不是长 crossfade。每个机位内部继续自己的行进；小幅衰减 roll kick 来自切点/落物事件。镜头追随桌面落物时，target 与 focal 都有局部响应。

**迁移**：先列出不同观察任务，再选机位；避免每句只是正面全景换形状。短促换机位要有清晰落点、前景视差与读字停留。上述时长是本曲实参，不是普遍最佳值。

### spacetime / stack：动静和景别的反差

实现：`spacetime.ts:renderLens / sheetCam / renderSheet`、`spacetime-lens.ts`；`stack.ts:render` 的 camera 分支（约 397–440 行）。

- spacetime 先固定仪器视角与极缓推进，之后才收束、透镜形变、穿入；再换成空间曲面上的升降/环绕，最后在拍点硬切到接近垂直俯视。俯视用来读清重新排列，慢螺旋只是辅助。
- stack 从陡俯视的深井进入三分之四视角，中途切高/低机位；停止事件后收窄 FOV、稳定构图，让原先的高速纵向运动真正“停下来”。

**迁移**：强烈运动前后安排稳定参考，不让每段都同样摇晃。大景别交代结构，中近景表达作用，极近景承担穿入；退到远景可以揭示刚才看不见的整体。

## 3. 转场首先是共享空间和状态

### 数字/字形变成下一场入口

实现：`hook.ts:drawNumberPhase / drawFinalPD / drawLids`（约 488–620 行）。

副歌重复同一语法，但每次出口为下一场定制：
- 第一轮把数字收束到下一场的爆发原点，再让末尾大字以相同布局/轮廓交给下一模块。
- 第二轮把数值面板压扁、移动并旋转到下一场眼睑接缝；接缝投影使用下一场的相机空间。画面闭合后，下一场沿同一接缝重新展开。
- 最后一轮把长数字压成一条横线，提前交到织机的纬线高度与信号位置。

**迁移**：出镜时先成为下一镜所需的起始几何；共享坐标、投影或布局 helper，别让两边各猜一个“差不多”的位置。对象变换需要对应关系，不能只在两图之间 dissolve。

### 递归穿入：下一场已在洞底实时存在

实现：`loom.ts:renderDroste`（约 387–454 行），与 `ilya.ts` 共用 `ilya-room.ts:IlyaRoom`。

递归版面每拍深入一层，在事件上扭转；临近出口时先解扭、再向底层加速/减速。洞底不是下一场的静态截图，而是以同一歌曲时间实时渲染的下一场空间。切点到来时，递归缩放抵达那个空间，后续模块继续同一个世界。

**迁移**：共享 sceneState(t)/cameraState(t) 和同一输入，前镜先将目标场景绘入 portal/屏幕/容器；在交界令屏幕映射收敛到下一镜的正式映射。检验颜色、焦点、投影、文字和运动方向；仅共用模型文件不足以保证接续。

### 拍点硬切与视线接力

`timeline.ts:makeTimeline` 从人声锚点推导 beat/downbeat 边界，当前主场景窗大多首尾相接，是硬切。引擎支持重叠淡化不代表成片所有转场都在使用它。该源码还留有小的吸附容差，不能把注释里的“绝不晚于词”当作没有容差的数学保证。

**迁移**：硬切需要上一镜的运动/轮廓/注视位置为下一镜铺垫，或以明确的尺度/明暗反差表达新段落。不强迫跨镜位置速度连续；只对意图连续的交接检查 C0/C1。相机内部的 hard cut 也要进入渲染器的 cuts 表。

### 片尾闭环

`outro.ts` 使用 plates 缩图倒序蒙太奇，最后调用 opening 场景的私有实例，在重新映射的时间下倒放并减速停到首帧。首尾裁切框也参与闭合。

**迁移**：重复使用起始场景函数，不凭最后一张相似截图宣称闭环。检查最后实际编码帧到首帧的布局、亮度、速度与声音连接。更改场景后重建用于蒙太奇的 plates；缩图不会自动更新。

## 4. 视觉风格为什么能支持镜头

整体可概括为“技术图版/雕刻线描的编辑式音乐影像”：同一色彩、字体和颗粒体系下，切换图表、仪器、官僚表格、钞票雕纹、线框室内、SDF 生物和织物等具体视觉语汇。冷静精密的外观与失控动作形成反差。

### 颜色有角色，明暗有段落

当前 palette.ts 的核心色：

| token | 色值 | 角色 |
|---|---|---|
| ink / ink2 | #0A0A0B / #151517 | 黑底与暗层级 |
| graphite / ash | #5E5B57 / #9C978F | 次要线与信息 |
| bone | #EEE9DF | 纸面、主字与精细结构 |
| signal | #FF4D12 | 主动作、危险、已唱强调和贯穿信号 |
| ember / blood | #FF8A3D / #C21D0B | 热核心与深色阴影 |
| acid | #D8FF3C | 单个特定事件的稀有例外 |

深底场景与浅色表单/纸币镜头形成章节性的明暗节奏；橙色角色保持稳定。新歌保留“有限色彩有明确职责”的方法，可换色，不自动禁止用户既定青/紫风格。

### 字体是多种叙事声音

Archivo 负责主体歌词和有力的尺度变化；IBM Plex Mono 承担机器、标注、表格；Cormorant Garamond 带来少量抒情/预言性语气；单线字体用于笔尖实际描写。字体数量的价值来自分工，不是数量本身。

主字可巨大且局部越界，辅助注释细小而克制；构图有强弱、疏密和不对称，留白容纳镜头视线。世界文字沿曲线/标牌/表面存在，机位为其阅读服务。源设计文档偏好实心清晰主字，但代码存在有目的的未唱轮廓/转场轮廓，不能简化成“任何描边一律禁止”。

### 质感从几何与材质规则生成

- 等高线随地形，高密度 hatch 随法线/表面与明暗，不能把统一噪点盖上去就叫版画。
- GPU line batch 的稳定细线、max blend 与物理像素 AA 防止交点糊成亮块。
- 发光集中在信号/火花，纸面与文字保留边缘；颗粒、halation 和轻微色差只作统一收尾。
- 纸张、图表、刻度、小注释和精密框线提供可信的图版语法；镜头之间变换材质语言，同时保持字体/颜色/母题。

这里的“克制”不等于每个镜头都少物体，而是复杂度集中在当下主体和它的作用上。

## 5. 贯穿母题与重复段落升级

spark 不是随机装饰：它在不同段落成为画笔、曲线信号、图表走势、金属线、引线。母题变换提供跨场关联；局部代码共享 _motifs，身份/位置接续仍需按各镜验证，不能宣称整片天然一个全局粒子 ID。

同样的副歌保留可识别的文字节奏，但改变尺度、压力、密度、明暗和出口；低能段可以刻意缩小并减速，升级不等于每次都更亮更吵。数值读数嵌入各场景的图表、表单或装置，避免不必要的永久调试 HUD。

## 6. 在我们的工程中如何落地

1. 从当前歌选能承载多个动作的主体/母题，列出每段的状态变化；不套 pdoom 的末日题材。
2. 先画取景与路线：同一场景的正面、侧斜、低角度、俯视哪些确有信息价值。镜头多样性服务动作，不为凑数量。
3. 在分镜阶段同时定义上一镜的出口与下一镜入口；能共享几何/相机函数就共享，跨后端则记录屏幕位置、尺度、朝向、颜色、光线与时间。
4. 快速出低成本 animatic：保留真实歌曲时间、机位、字幕布局和切点，减少几何/后期复杂度；确认节奏后再加纹理与模糊。
5. 网页二维/2.5D 用 Multiplane；GPU 线场或 SDF 用 Three.js/ModernGL；实体照明、景深与复杂空间用 Blender。相机机位/落点由同一设计表驱动。
6. 对快速镜头先查目标是否在画面内、相机是否穿物、文字是否可读，再加子帧曝光；不能以模糊掩盖错误。
7. 输出切点前后若干帧、动作起终点和连续片段；共享空间转场尤其比较屏幕映射和速度。单张 contact sheet 只能证明构图抽样。

## 7. 避免学偏

- 不把“全片同一色调”当作唯一风格，也不把轨道相机当作所有镜头的答案。
- 不让 every-frame 抖动、glitch、flash 替代入点/落点/停顿。
- 不强迫所有镜头连续；设计好的硬切与连续穿入各有任务。
- 不让关键歌词永远贴在屏幕底部，也不为了融景把词变得读不清。
- 不把设计文档旧设想直接当当前实现：以当前源码和实际画面互相核对。
- 不复制作者的平台启动参数、60 fps 假设、固定歌曲数据或素材许可到新项目。技术适配见 [rendering-techniques.md](rendering-techniques.md) 和 [local-tools.md](local-tools.md)。
