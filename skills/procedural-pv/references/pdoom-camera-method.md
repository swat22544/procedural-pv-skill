# pdoom：把镜头和视角设计落实到制作

> 公开版阅读约定：`<…>` 是待配置的路径占位符；文中原项目文件名属于所指参考仓库或本地案例，不表示随本 skill 附送。原研究的抽样与运行记录仅说明当时的验证范围，不代表你的环境已经通过。跨机器使用先读 [环境接入](environment-setup.md)。

用于设计分镜、同场景多机位、跟拍/揭露/急停、歌词融景，以及诊断“镜头很多但没有观看重点”。风格总览仍见 [pdoom-design.md](pdoom-design.md)，逐场源码例子见 [pdoom-shot-cases.md](pdoom-shot-cases.md)。前后状态交接使用 [FrostNova 细则](frostnova-transitions.md)，这里重点解决为什么这样取景、何时改变观察位置。

## 1. 每次变机位都要改变观众能读到的信息

先写一对句子：**这一镜开始时观众知道什么；结束时多看懂了什么。** 然后决定是否需要换角度。下面是根据源码归纳的方法，不是把某种角度固定等同于某种情绪：

| 此刻的观看任务 | 可选取景方式 | 画面需要的依据 |
|---|---|---|
| 读清关系、步骤或文字 | 正面、接近平面、较小透视压缩的构图 | 完整词组、可追踪路径与读图保持 |
| 看出体积、层次和作用方向 | 三分之四、侧向移动、适度前景遮挡 | 至少一个近景参照和一个远处落点 |
| 从熟悉局部发现巨大整体 | 先近景隐藏范围，再拉远揭示 | 被跟踪局部始终可辨，最终整体有足够留白 |
| 感受通道、挤压或速度 | 沿通道推进，左右/高低机位交替 | 墙架等近物掠过、清晰消失点、有限遮挡 |
| 检查某个错误、动作或关键字 | 收紧到局部，减少倾斜，保持可读角度 | 动作开始前可定位，完成后留出观察时间 |
| 表达关系倒置或失稳 | 在明确事件上改变 roll/参考系 | 先建立方向参照，翻转有落点和后果 |
| 读清重排后的整体结构 | 从斜视切至俯视或工程立面 | 主体运动收束，新的关系能被一眼比较 |

同一场景可以先后承担多个任务；不用为换角度每次新建世界。也不强迫每句切一次或用完整一圈绕转展示模型。pdoom 的 room、shoggoth、stack 都会保留主体而改变观察任务，具体分段见案例页。

## 2. 先辨认“相机”实际是哪种实现

| 实现 | 源码例子 | 可以做什么 / 需要注意什么 |
|---|---|---|
| Three.js 透视相机 | loss、stack、spacetime 的 sheet 阶段 | 真正空间视差、遮挡与近远关系；检查碰撞/裁剪/FOV |
| 自建针孔或 raymarch 相机 | room、ilya-room、shoggoth | position + 正交基 + 像素 focal；CPU 投影与 shader 射线必须同一约定 |
| 二维图版取景 | ascent、loom 的 tree 阶段 | 平移、旋转、缩放和屏幕锚点；不宣称产生真实三维视差 |
| 二维图版加透视形变 | leftturn 的 map + keystone | 保持地图/文字同一变换；临近出口可将倾斜收至零 |
| 屏幕空间透镜/后期 | spacetime 的 lens 阶段、局部 post zoom/roll | 变形可以表达穿入/失稳，但与移动真实相机分开记录 |

不要依据字段名推断单位：room 的 `f` 是逻辑像素焦距；ascent 的 `cam.z` 与 lens 阶段的 `Z` 是倍率，后者越大图像越大，并非相机离物体越远。设计文档的“仰跟、吊升”可以描述观看感受，实际实现要沿代码确认。

垂直 FOV 与针孔像素焦距的对应为 `f = (H/2)/tan(FOV/2)`，H 必须是同一 viewport 的高度。room 在不同机位改变 f，是真正针孔投影视角的变化；不能把 520/1250 当角度或毫米。逻辑 1920×1080 与输出物理像素另行缩放。

移动 position 会改变视差/遮挡；只改变 focal/FOV 是改变视野；post zoom 是输出图像变换。要做保持主体大小而改变背景关系的推拉变焦，需先满足屏幕占幅约束，不能把任何“推进且改 FOV”都叫作已实现该效果。

## 3. 把位置、目标、尺度和滚转分开编排

为一段运动选择一个主动作，其他通道服务它：

- **position(t)** 决定观众处于哪里、经过什么、前景怎样掠过。
- **target(t)** 决定注意力指向谁；可以先于 position 转向，也可以从主体逐步移向最终落点。
- **FOV / focal / zoom(t)** 决定占幅和视野；正倍率的大跨度变化常用对数插值，角度与距离仍按自己的含义处理。
- **roll(t)** 改变水平参照；将大幅滚转绑定倒置/失稳事件，小 kick 使用衰减包络。别把全部时间都填满抖动。
- **post/overlay** 是另一个层次；它们的缩放、偏移也影响最终构图，不能只检查原始相机。

loss 的坠落先让 target 追信号，position 稍后下降，落地前 target 再接向地形；room 的落物同时短暂牵动 target 与 focal。它们都说明各参数可以共享事件但使用不同曲线/窗口。

## 4. 跟拍不等于永远把主体钉在中心

镜头与主体同速同向时，主体的动作可能在画面中被抵消。根据观看任务选择下列关系，并明确退出条件：

| 关系 | 源码依据 | 迁移用法 |
|---|---|---|
| 等待入画，再开始追 | leftturn 的 hold/softPos | 先让环境成为参照；主体到预定屏幕位置才接入追踪 |
| 留出前进空间 | leftturn 的 lead、loom 的 tip offset | 让主体位于偏侧/偏下的位置，为即将出现的路径与文字留空间 |
| 主体先冲，相机略迟后 | ascent 的 `headY(t-.035)` | 用小而有界的迟后显出冲量，随后收束到阅读构图 |
| 冻结旧目标，揭露新关系 | shoggoth 在 tBack 固定 mask 锚点 | 主体被拉走时可留在原观察位置，看它与环境的关系，而非追着飞走 |
| 从局部追踪转为整体观察 | loom tree、leftturn reveal | 从动作尖端转向全体 bounds，完成后保持最终信息布局 |

这些不是可任意叠加的装饰。先写“何时开始追、何时不再追、落点在哪里”，再选择插值。源码的 35ms 迟后、某一拍的 offset 都是本片实参。

## 5. 歌词和标签参与构图

pdoom 让机位为文字分配空间：room 的牌面从低位到正对近景；ilya 将电脑放右侧、左上留暗部；shoggoth 最后换正面机位给左侧标签让位；spacetime 将当前朗读位置保持在可读的前弧。

制作时给文字明确角色：

- **世界中的文字**：跟随载体的透视、运动和适当遮挡。预先约定最小投影字高、可接受的缩短/斜切、关键字可见时段；不要求每个次要字永远无遮挡。
- **说明标签**：以主体投影为锚点，但放在可读区域，引线与主体相连。相机目标可以偏离主体中心以腾出空间。
- **稳定字幕/关键覆盖文字**：保持阅读层职责；快速穿入时可以先保持清晰、在落入下一场之前退出，避免被递归无限缩小。

不要仅靠最后加黑底修复拥挤。先检查世界/文字的相对位置、摄影角度和留白。局部字形仿射近似、真实文字平面与曲面文字分开命名；可读性依据最终投影，不能依据模型里的字号。

## 6. 镜头节奏：启动、转移、落点、保持

主场景窗由 `timeline.ts` 从歌词锚点和拍网格生成；同一场景内部还有 beat、downbeat、词头、音节、落物等事件。先选实际事件，再定义窗口。不是所有换机位都在下拍；源码的 cut 容差也允许落在词头之后极短距离。

分清三种连接：

1. **硬换机位**：分支直接改变相机。用于揭示新关系、改变观察任务或突然停落；检查切后主体定位与文字阅读。
2. **短促重构图 snap**：例如 room 的 .09–.16 秒 outExpo，起点接上一机位尾态，终点追上按自身时钟行进的新机位。它与 dissolve、长巡航不同。
3. **持续运镜**：同一状态内推进、环绕、吊升、拉远或跟踪。设计可见的目的地；需要接续时再检查 C0/C1。

“停止”须说清是哪一项：stack 停止纵向落层和落点抖动后，仍允许缓慢推近；它不是所有相机通道都冻结。阅读保持也可以是低运动量的稳定取景，不必一律绝对静止。

运动模糊在路径和时序成立后再调。快速小范围冲量、屏幕 shader blur、世界几何拖伸和整帧快门积分分别记录；本库有多种混合用法，不直接复制成重复采样链。

## 7. 用一张导演卡落实每次视角变化

扩展当前镜头表即可，不强制另建框架：

```yaml
id: existing_shot_id
knowledge: {before: ..., after: ...}
subject: {id: ..., action: ..., visible_reference: ...}
view: {scale: ..., azimuth: ..., elevation: ..., projection_kind: ...}
composition: {subject_anchor: ..., extent: ..., text_region: ..., look_room: ...}
motion: {primary: ..., target_rule: ..., lens_rule: ..., roll_reason: ...}
follow: {begin: ..., lead_or_lag: ..., release_or_freeze: ...}
timing: {prepare: ..., trigger: ..., arrival: ..., read_until: ...}
connection: {type: hard_cut_or_snap_or_continuous, effective_cut_times: ...}
exit: {carrier: ..., next_projection: ..., new_action_after: ...}
qa: {screen_samples: ..., readable_interval: ..., boundary_expectation: ...}
```

先确定开始/结束构图和阅读窗口，再生成中间路径。长距离转移可以像 leftturn 那样中段暂时扩大视野、接近落点再收紧；不要同时无约束地改位置、目标、roll 和尺度。需要前后共享状态时继续填写 FrostNova 的交接字段。

## 8. 制作与验收的具体检查

- **机位是否有用**：把镜头变化临时替为固定机位/硬切对照，判断新角度是否帮助理解动作或空间。不按机位数量评分。
- **最终屏幕状态**：输出主体锚点、包围盒/轮廓、投影深度、阅读区占用及真实 viewport；加上 shader/post 偏移再检查。二维 z 倍率与三维深度不能混算。
- **动作边界**：在事件 `te−ε / te / te+ε` 以及实际输出帧上检查。stack.pos 的源码在精确 beat/stop 时刻存在分支贡献缺失，已通过数值样例复现；迁移时统一半开区间并修正，不照抄为连续函数。没有渲染证据时不称原片肉眼可见坏帧。
- **视线与阅读**：入口前知道看哪里，落点后能读完关键内容；检查字形缩短、倒投影、前景遮挡、焦距变化后的裁切。先关模糊/强光看清路径，再开正常后期复核。
- **空间约束**：查相机穿墙/穿地、目标跑到背后、近裁剪、极端俯视下 up 基退化。源库的局部保护并非全场碰撞系统。
- **切点曝光**：pdoom 当前 Scene API 没有内部 cuts 注册表，engine 的快门采样会查询切点两侧。我们移植时要把场景内外有效硬切交给所选渲染器的 cuts/快门限制机制；这是制作要求，不是声称源库已经实现。
- **先预演再精修**：用真实歌曲时序和文字布局做低成本机位预演，确认观察任务、节奏、阅读和出口，再加 hatch、SDF、粒子与高采样。HTML/JS 输出仍走本机 Multiplane；Blender 镜头沿原生链路，工具不替代导演选择。
