## 1. 先写发生了什么，再写怎样动

从案例归纳的分镜句式是：**A 已有的某物受到动作 → 脱离原位置成为载体 → 沿有意义的路径到达 B → B 留下可见变化 → 该变化使下一动作成立。**

例如：盾牌点被取走装入权重格；文字汇聚到损失曲线的原点；用户消息被改写，之后改写权反过来掌握在角色手中；记忆先被取出，随后才能被切碎并擦除。每次移动给观众一个“从哪里来、到哪里去、为什么改变”的依据。

分镜至少说清：

- **出发前的可识别物**：轮廓、文字、颜色、位置或此前事件使它有身份。
- **动作的发起者与触发**：谁选中、拉走、输入、消耗、拒绝或释放了它；声音只负责触发时刻时，不把节拍误当作故事原因。
- **注意力交接**：先抬亮/轻放大/预动，再搬运；背景信息在合适的方向换手。
- **落地后的后果**：格子被占用、曲线开始生长、消息被保留、权限被交出、旧物真的消失。载体离场后状态仍成立。
- **读懂结果的时间**：放大、飞行和冲击并非全程动作；用适合当前歌词的停留让观众认出改变。

若无法说明 B 为什么从 A 产生，可以采用明确硬切或平行蒙太奇；不要强行把任意两物做成形变。双画面也可表达比喻、反差而不是物理因果，分镜标明关系类型。

## 2. 沿最终出片入口确认“谁真的在画”

本片有效链是 `build.py → dsh_her.install → pv_full.install → v2/各section → dsh patches → frame → finish`。当前运行得到 **97 个正时长 shot、74 个 Cut 实例、2 个 FINISH 回调**；README/HOW_IT_WORKS 的“96”是说明口径，不能用来推断当前数量。

重要优先级：

1. `v2.active_cut(t)` 返回 CUTS 顺序中第一个 active 的实例；`[T-pre,T+post)` 是半开窗口。重叠不会自动叠加或混合。
2. `_frame` 优先调用 cut；无 cut 时才用该镜的 OWN renderer；再回退普通 `cuts.body`。cut 返回成品图像时也可提前结束常规分层。
3. 常规路径依次组合 content、under carrier、主体窗格、shot overlay、上层 carrier，再加 chrome/post。不能只看 carrier 的函数就判断它最终被谁挡住。
4. dsh 实际安装顺序是 `fix → r1 → mem → e → f → g`；名为 d 的可选文件在此提交不存在。最后 FINISH 第一个返回非 None 的回调接管输出。

因此“角色粒子聚成人体”在最终版可能已改成“粒子飞向窗口头像的矩形区域”；“舞者行流出”也可能已替换为真实聊天窗口的行。研究、迁移和截图均记录最终 renderer，而不是只读最早同名函数。

## 3. 区分四种连贯性，按需要选用

| 连贯方式 | 实现依据 | 应当验证 |
|---|---|---|
| 同一对象/同一格的接力 | 稳定索引、一一对应落点、持久 landed 表 | 身份、数量、位置、落地时间及后镜保留 |
| 同一几何关系的演变 | 两镜共用曲线/投影/相位公式 | 两侧用同一个时间、坐标系与参数；不只轮廓相似 |
| 形态或区域匹配 | 采样轮廓、排序配对、取模分配、冻结目标 | 是否存在多对一/一对多；目标是否仍移动；叠化怎样遮蔽近似 |
| 语义与注意力接续 | 关键词、色彩、光标、左右主次或情节反转 | 观众是否还能辨认关系；不需要强称物理同对象 |

本片 C02 的盾点→格子有明确 cell 对应；C12 将 1400 个点按取模分配到有限鲸字起点，不守恒粒子数量；C08 的部分词流目标是预采样位置，不是对 live token ID 的持续跟踪。三者都可有好效果，但工程保证不同。

迁移形变时先建立映射策略：轮廓按弧长重采样、网格按行列、路径按参数/弧长、文字按布局包围盒，或有意做区域采样。先约定出生/合并/消失，再写插值。数量不同不能用随意 zip 后就宣称逐元素连续。

## 4. 转场临时接管，落地交回后镜

`cuts.body` 合并 `SHOT_HOOKS[shot_name] → SHOT_HOOKS[shot_index] → per-call hooks`。后者覆盖前者；同一 scene 被复用时，以镜头 ID 定位可以避免误改所有出现。

载体存在期间，在旧/新场关闭相应副本，由 carrier 层独占绘制。落地后停止绘制 carrier，接收场在同一落点接手并保留新状态；必要时安排很短的重叠淡交，但明确它是视觉交接。避免原物、飞行物和目标物同时存在造成三份副本。

将落地时间放进永久的场景输入：C02 的 landed 表控制格子何时出现，之后扫描才启动；C87 把格子送到学习曲线原点后，曲线才生长。落地不是仅在转场末帧“看上去到了”，还需要后镜下一帧保持。

本库 `DELAY` 的准确作用是 `te=max(shot.start,t-delay)`，它修改传给后镜的**整份场景时间**，不只局部进度。转场自己仍读歌曲 t；后镜如有绝对时间事件，也必须统一换算。C88 取前镜状态时显式扣掉 C87 的延迟，可学这种时间口径核对。新工程可分开 song_t / scene_t / event_t，避免隐式重定时。

函数缓存、永久 hook 与逐帧 hook 分开：`body` 调用前设临时 HOOK，finally 清理；持久输入来自固定配置/时间表。不要把上一帧的临时对象当作下次乱序调用的隐式前提。

## 5. 背景更换也沿着动作传播

`kit.reveal` 不是单一全屏淡化：每个格有自己的开始时间 `delay(x,y)`，格内在短窗口混合前后图，并可在有墨迹的格上画过渡解码字符。默认 8×16 格与 .09 秒属于该片参数。

三种时间场的叙事用途：

- **从接触点向外**：`t0+distance/speed`，让落点仿佛激活新的画面。
- **向中心收束**：远格先退出、中心最后，配合文字/粒子被吸收。
- **沿动作方向推进**：投影距离除以速度，让整理、写入或擦除的方向与载体一致。

载体路径、背景换手、文字持留可有不同窗口。窗口长度至少覆盖最远格的传播、最后一个错峰元素的落地、落定/淡交与后镜接管；不能只看中央元素完成时间。reveal 只覆盖整格区域，边缘余数另行处理。

用背景差值提取 ink 可以搬走笔画而不带整张矩形截图；需要真实完整 alpha 时直接使用透明层。前后底色/后期不一致会破坏差值抠取，必须用同一背景与时间检查。

## 6. 双画面共同讲一个动作

左窗不只是字幕框：它承接原角色窗格的几何运动，窗口内容变化也能成为载体；右侧机制图解释、回应或反讽左侧行为。使用共同的事件 ID 协调两个区域，同时明确哪边先发生、哪边是结果。

本片亮度并不对称：左主导时右区降到 .42；右主导时左窗 alpha 为 .7；通常在 .25 秒内渐变。最终 G 段还会局部恢复 logout 按钮的亮度，黑场另有提前返回。这些都是具体导演选择，不能提炼成“所有辅助画面统一42%”。

跨 HTML/PIL 的交接使用 DOM 实测的 `cursor.json`，加窗格原点/inset 变为舞台坐标，再接入网络节点与推拉路径。像素尺度、布局、字体、alpha 和取整共同决定最后落点。换字体或窗格宽度后重新测量；别凭 CSS 的 nominal left/top 猜屏幕锚点。

让早期行为在后段改变含义：同一输入/选择/改写方式由谁执行、谁有权停止，可以形成连续叙事。重复构图与动作词有助于观众识别关系变化，不必每段都换新特效。

## 7. 实作时填写的最小接力契约

```yaml
transition_id: ...
meaning: 原物受何种动作，落地后变成什么
relation: identity | shared_geometry | region_match | semantic
source: {shot_id: ..., element_ids: ..., time: live_or_sampled, screen_anchor: ...}
mapping: {rule: ..., count_change: ..., target_time: ...}
carrier: {path: ..., phase: lift_fly_settle, owner_window: ..., layer: ...}
receiver: {anchor: ..., visible_from: ..., persistent_state: ..., own_action_from: ...}
clocks: {song: ..., scene_delay: ..., event_conversion: ...}
background: {origin: ..., time_field: ..., last_cell_finishes: ...}
attention: {lead_region: ..., read_hold: ..., lyric_overlap: ...}
checks: {before: ..., landing: ..., after_handoff: ..., last_staggered_item: ...}
```

只填写当前镜头真正需要的字段。新工程可用显式状态函数/场景协议实现，不要求照搬此库的内存 monkey patch。让两镜读取同一份契约比复制落点常数更易维护。

## 8. 怎么验收“连贯”

- 先看出发前、预动、在途、落地、交回、后续动作；连续小片段包含双方完整窗口。单张漂亮静帧不能证明接续。
- 同一画面层级中比较最终屏幕位置、形态、尺寸、颜色/alpha；形状一致但主体身份或语义反转，也要标明是有意选择。
- 测最后一个错峰元素、最远格、窗口精确端点和对应编码帧。检查相邻 Cut 重叠的优先级；本片 C14/C15 有约 .1346 秒重叠，且 C14 最晚圆生长超出自身窗口，不能把原片概括为所有边界数学连续。
- 比较动画层与后期后的图像；辉光、字符解码、alpha 混合可增强接力，不能替代错误落点或掩盖对象重生。
- 抽查乱序、重复时间和片段起始预帧；报告抽查范围。源项目声称每帧纯函数，不等于完整混合链已证明所有时刻无调用历史依赖。
- 本片原生是 1280×720 / 24fps；4K 为三倍最近邻上采样，60fps 为可选运动补偿。新作自行选择目标帧率；原先按帧写的停留、跳跃与截图索引要重新换算。
