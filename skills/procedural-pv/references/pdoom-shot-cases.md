## 1. loss：目标先追动作，相机随后进入空间

源码：[loss.ts:520–590](https://github.com/mexicat/pdoom-video/blob/fa164b74fd0b26a99375715b619c55b4a0fb3d05/app/src/scenes/loss.ts#L520)，事件选择在 238–266，投影与地形分别在 setCam/proj、terrH。

| 阶段 | position / target / 镜头参数 | 观察任务 |
|---|---|---|
| 图表 | chartCam：FOV30，窄视角，轻推与少量偏移；不是严格正交 | 先读走势和正在写出的内容 |
| 下坠 | position 从 tDrop+.04 开始，以 inOutCubic 走向 landCam；target 从 tDrop 即追 spark，末 .2 秒接向落地目标；FOV30→32 | 先看见信号跌落，再被相机带离图表 |
| 入谷 | 初始较高斜角，yaw .35→1.2、pitch1.02→.66、距离11.5→12.5，目标从落点转向写字路径 | 揭示曲线已经成为峡谷空间 |
| 低处沿谷观察 | tCut1 直接改分支，距离约9.6、FOV36，随后目标逐渐指向盆地 | 从“看到地形”变成“沿地形看前进方向” |
| 盆地/倒置/俯冲 | tCut2 再换机位；roll 在 tRoll 起 .45 秒转 π，再有 .13rad 余转；向坑底收距离并扩大FOV34→64 | 用参考系改变承担关系倒置，随后深入最低点 |

主导动作与辅助动作有层次：在坠落段是 target 先转、位置后动；到了峡谷，目标从歌词路径移向信号；末段才允许大幅 roll 和广视野。不是每段同时开启全部参数。

`camera` 对地形中心及四个偏移采样取最高值+1.4，限制相机高度。它是局部离地保护，不能证明所有路径避障，也不自动保持速度平滑。迁移时先验证文字路径、信号与落点能在取景内相互指认，再调整地形密度。

**可用导演句式**：先建立可读的平面关系 → 动作打破平面 → 目标先回应 → 相机进入动作所在空间 → 新机位揭示下一目标。

## 2. room：一小段歌词中的五个观察任务

源码：[room.ts:644–761](https://github.com/mexicat/pdoom-video/blob/fa164b74fd0b26a99375715b619c55b4a0fb3d05/app/src/scenes/room.ts#L644)，文字布局 buildBoard，投影/裁剪 proj/clipSeg/planeAffine。

这里使用自制针孔相机 `p/tg/roll/f`，f 为逻辑像素焦距；不能把表中的 520、1250 当 FOV。

| 机位 | 空间关系与动作 | f / 接入方式 | 为什么需要这次变化 |
|---|---|---|---|
| 门后冲入 | 跟在被冲开的门后进入，roll -.5→-.02，沿过道前进 | 520→900；首段无 snap | 相机入场有可见原因，建立通道方向 |
| 右通道 | 相机在右侧，目标偏向左上，书架近景掠过 | 860→900；.13s snap | 用视差和遮挡感受通道速度 |
| 左低位 | 高度约 .6，向标牌/出纸装置仰视 | 780→800；.12s snap | 装置开始工作时改变尺度与作用方向 |
| 标牌近景 | 位置抬高，正对牌面，进一步推进 | 1150→1250；.09s snap | 让核心文字成为明确落点 |
| 桌上高位 | 高度约3.15，绕桌加速，目标逐步下降，后段roll增强 | 基础700，事件调制；.16s snap | 从牌面扩大到落物、书本和桌面变化 |

`keyAt(t)` 在 snap 窗口用 outExpo 混合双方的 `shotKey(...,t)`。**实际前四段的 p/tg/f 由局部进度钳到末态**，首段 rollSpring 可继续余振；新机位从自己的 t0 起已在推进。准确方法是“从旧机位尾部短促追上新机位当前状态”，不能概括为两端一直无限移动，也不能把新机位冻结到 snap 完成后才启动。

后一高位 orbit 的方位使用 `.6u+.4u²` 加速，距离逐渐收紧；落物时 target 只按 .25 的权重牵向桌面，focal 有短促增强。小幅 kick 和落物响应附着在主路径上，而非取代路径。

书本滑出还会依据触发时刻的相机筛选近处可见候选（buildSlides），让装饰动作发生在观众能看到的位置；不是在全场随机忙动。世界牌面、卡片使用投影/局部仿射绘制，需要验证近裁剪和角度失真；不能当任意曲面上的精确贴字。

**迁移重点**：给每次换角度不同任务；近景前景负责速度，低位负责装置关系，正面负责读字，高位负责展示影响范围。快节奏不等于没有落点。

## 3. shoggoth：先隐藏整体，再揭露，最后允许检查

源码：`app/src/scenes/shoggoth.ts:155–187,213–272,438–525,655–723`；字面深度与遮挡见 `shoggoth-glsl.ts:424–452`。

| 阶段 | 实际镜头选择 | 交给观众的信息 |
|---|---|---|
| A 贴近面具 | 沿面具法线接近，距离约.95→.9；更早还有7.5→.95冲入 | 先只看到小而熟悉的面具，暂不暴露整体规模 |
| B 拉远揭露 | 位置 .75s outExpo 后退，target .65s 转向本体，roll仅小幅变化 | 面具成为大结构上的小物体，尺度关系改变 |
| C 左侧低位 | tCut2 在拉远后的下拍直接换机位，约pos[-2,-.6,3.9]，roll .12 | 用另一侧与较低观察点强化本体空间关系 |
| D 正面检视 | tWith 词头直接换正面慢推，target偏左，本体落在画面右侧 | 左边留给逐个眼睛的标签，观察任务转为检查 |

tBack 后，A 端的面具位置/法线固定在 `maskAt(tBack)`。面具被拉走时，相机仍从原近景位置退出，不被它带飞。**是否继续追踪主体本身也是导演决策**：需要揭露主体与整体关系时，冻结旧锚点比追得更紧有效。

大关键词位于世界文字平面中，按射线/文字平面求交，并用本体与面具深度遮挡；左侧标签则以眼睛投影连接引线、保留屏幕阅读布局。两类文字的相机与遮挡职责不同。CPU 单字形 `glyphAff` 仍是局部仿射近似，不夸大为任意曲面的精确透视文本。

**迁移重点**：在分镜上写“现在故意不让观众看到什么”“下个角度揭露什么”“最后需要逐个检查什么”，再决定拉远、低位和正面留白。

## 4. leftturn：等待、追逐、制动和揭示都在同一张图版

源码：[leftturn.ts:137–289](https://github.com/mexicat/pdoom-video/blob/fa164b74fd0b26a99375715b619c55b4a0fb3d05/app/src/scenes/leftturn.ts#L137)，配合 leftturn-map.ts、leftturn-gantt.ts。

这里的相机是二维 map pan/rotation/zoom 加 keystone：先旋转缩放为 fx/fy，再除以 `1-K*fy`；地图 shader 与叠加文字使用相容映射。它可以表达追逐、转向、升起看全貌的观感，但不等于真实三维相机吊臂。

1. **等动作入画。** 先从屏幕进入位置、追踪位置反推图版坐标，camLand 用 softPos 将固定观看位置平滑接入追随；环境不会从第一帧就与主体同速。
2. **跟随急转。** turn、lead、zoom 各有事件曲线。转弯后 sparkS 用三次 Hermite 保留入场速度并以零末速度落到目标；镜头再给落地响应。
3. **拉远揭露。** camWide 让刚才的坑成为整张面具地形的一只眼。局部与整体是同一张图版，观众能看懂重新解释。
4. **转移到另一处信息。** 图版到进度表的 whip 混合相机后，再令 `zoom *= 1-.45*sin(πk)`：中段倍率降至常规插值的55%，暂时扩大可见范围，两端恢复。不是把画面一路以最大倍率甩过去。
5. **由流程转向失败位置。** camTrack 让 playhead 位于左侧，为前方进度留空间；camSlot 按音节收紧空槽，叙事重点由“正在运行”变为“缺了一个环节”。
6. **反算出口。** camEnd 由下一镜 caret 的位置与高度计算缩放和中心；出口前 rot 与 keystone 都归零，空槽才落入下一镜的准确构图。

最后阶段的计算关系可复用：`zoomEnd = caretHeight / slotHeight`；若无旋转/倾斜，`cameraCenter = slotPosition - (caretScreen-frameCenter)/zoomEnd`。本片的 .07/.08 秒收束顺序是让倾斜先退、最终锚定后到；改版时检查宽度、形状、颜色和背景，中心与高度一致并不等于整个画面一致。

**迁移重点**：用下一镜的实际投影约束当前镜头出口。`screenToWorldOffset` 处理旋转/缩放反算；keystone 不为零时还需完整逆变换，不可直接套无倾斜公式。

## 5. spacetime：改变观看模式，保持当前文字能读

源码：`app/src/scenes/spacetime.ts:lensAt(428–477),renderLens,sheetCam(707–732),renderSheet,drawFlowType`；`spacetime-lens.ts:64–71,107–110`。

前半先用相对稳定的仪器取景建立参照，再收束波形、放大透镜、进入暗中心。`lensAt` 的 Z 是画面倍率，uF=1400 是网格反投影的像素焦距；pitch 作用于网格平面，文字采样并没有被统一放到同一完整三维倾斜平面上。

临近 tM3，将暗中心半径 Rs 推至1500，借满幅暗区域遮蔽模式更换；tM3 直接从 renderLens 切到 renderSheet。这里可学**用遮挡/占幅完成换世界**，不能声称同一真实三维相机从透镜内部连续飞出。

sheet 的三段机位：

- **从喉部升出**：target 高度约-4.2→-2.2，距离7.5→18.5，俯仰1.45→.72，roll -.9→-.06，FOV50→34。先有接近轴向的压迫视角，再打开成高斜视图。
- **侧斜看加速流动**：tCutB 直接换分支，距离约15.5递减、俯仰约.42，观察流向与空间曲面。
- **俯视看重排结果**：tTop 再硬换机位，pitch约1.5，距离先20→23再推进，roll持续缓转。俯视承担结构阅读，不能仅说“又转了一下”。

环形文字不是放在固定圆周后任其转走：每帧把朗读 head 对到相机前侧 `front+.3`，跳过投影反向的字形 `qb.x<=qa.x`，按压缩率 .28→.62 渐显，并让后方旧字渐退。这样相机可以换角度而当前词仍主要落在前弧。

**迁移重点**：先确定哪个词/对象此刻必须在可读区域，再让其局部相位跟取景协同；这会改变世界里的排布，属于主动编舞，不是纯粹固定世界的摄影记录。

## 6. stack：用观察角度与透视变化表现“停止”

源码：`app/src/scenes/stack.ts:109–198,364–440`。phaseAt 直接选择 A/C/D/E，没有通用相机混合。

- A 从较陡斜俯视进入三分之四：pitch .98→.42（并非严格垂直俯视），距离25→17.5，FOV40→34；长音期间继续小幅环绕。
- C 换较高、较远机位，观察落层的重复结构；D 换较低、更近机位，增加方向与景别反差。
- E 在停止事件换近工程立面：pitch .1、yaw .2、FOV19、roll0，同时移除落点抖动。纵向落层停止后，仍有延迟慢推；“停”的重点是落层与冲击，不是相机所有参数恒定。

节奏并非机械每拍一层：首词阅读不够时删除过早的首拍落层；最后长词未结束时延后下一机位到词尾附近。停止后的模块错位也稍后启动，先让观众辨认“停住了”。这些按语义保护阅读的例外，比固定剪辑频率更值得复用。

数值边界：原 pos() 的 beat 预动仅在 t<事件时加入，而事件累积在 dt<=0 时跳过，导致精确时刻可缺 .22 步；stop 的同类分支可缺1步。已做数值复现，未据此判断原片实际可见。改写时检查精确事件、左右极限及曝光子帧，不能因为函数注释写 continuous 就直接采纳。

## 7. ascent：用轻微迟后显出主体冲量

源码：`app/src/scenes/ascent.ts:headY(275–290),camB(293–319),w2s(321–322)`。

先将上一段竖瞳的局部匹配到价格线，倍率从8按比例退到.8，同时从期望的屏幕坐标 sx/sy 反求平面相机。随后价格按音节冲高，镜头用 `headY(t-.035)` 追随，让主体短暂领先；最后脱离追随，构图落到整张月面图版。

这里 cam.z 是二维 zoom；向上运动来自平面坐标取景。局部 blur 的 uVel 用相机前后 x/y 差近似，不包含完整缩放速度，不等于通用三维运动向量或整帧快门积分。

**迁移重点**：相机与主体不同步可以让力道可见，但应限定迟后幅度并处理进入/退出该关系的边界，最终留出稳定的阅读构图。

## 8. loom → ilya：从分支局部到全貌，再进入已存在的空间

源码：[loom.ts:view/renderDroste](https://github.com/mexicat/pdoom-video/blob/fa164b74fd0b26a99375715b619c55b4a0fb3d05/app/src/scenes/loom.ts#L177)、`loom-glsl.ts`、[ilya-room.ts:255–313](https://github.com/mexicat/pdoom-video/blob/fa164b74fd0b26a99375715b619c55b4a0fb3d05/app/src/scenes/ilya-room.ts#L255)。

tree 阶段用二维取景跟着生成尖端，让尖端在中心右方、文字留在后面；随后根据整棵树 bounds 同时考虑宽高，算 `min(可用宽/树宽, 可用高/树高)`，在拍点拉远到全貌，再给少量落稳推进。它是“跟着一条选择走 → 看见所有未选分支”的信息揭示。

递归阶段在每拍深入、事件扭转后先解扭，最后用 inOutCubic 接到 `TERM_LEVEL=5`。洞底调用共享的 IlyaRoom，以当前歌曲时间实时渲染；解扭后的映射为中心缩放 `k=s^(zoom-TERM_LEVEL)`，切点 k=1。覆盖文字在切点前退完，避免入口已满屏却仍残留上一段标签。

要同时接住三件事：**空间内容使用同一状态函数、内部投影映射抵达目标、外部后期与文字归位**。本次函数 mock 检查了同 t 调用和单位映射端点，未运行 GLSL 的完整像素比对。

IlyaRoom 随后的机位也有观看任务：

1. 在屏幕后停留，让观众看到外壳细节；到指定词头才加速绕到前方。
2. 随盖子关闭逐步降低机位，target 从屏幕中心移向缝，再移向指示灯；视线追踪的是信息消失的路径。
3. 通过沿 camera-right 方向偏移 target，把电脑放到右侧，给左上歌词留暗部；缝收为点之前再居中，以便交给后段。
4. 指示灯退出后转到剧场的固定观看关系，再由帷幕缝收束成中心信号。room→theatre 是状态分支切换，不把全部后半段也归为同一条连续相机路径。

**迁移重点**：共同 scene/camera 状态适合真实入口；而“暂时不让观众看到屏幕正面”“目标从面到缝再到点”则是叙事安排。共享模块只保证规则来源相同，不能替代最终构图与颜色验收。

## 9. hook 与 outro：重复段落的出口应为目的地定制

`hook.ts:487–618,777–783` 为每轮副歌准备不同出口：收束到 room 的信号原点；压扁旋转到 ascent 的眼缝；低能轮次让灯丝退出；末轮将长数字拉成 loom 的纬线并摆好 spark。

这里存在两种工程现实：Loom/Ilya 真正共用 IlyaRoom；hook 的 ROOM/EYE/THREAD 参数却是**手动复制**目标模块的几何约定。不能把后者写成已共享一个 helper。迁移时优先共用契约；必须复制时加双侧投影检查，目标镜头改版后同步出口。

`outro.ts:764–796` 先倒序播放 plates，再调用 opening 私有实例；倒放时间 tau 不只驱动画面，还重新查询该时间的 beat/bar/audio features，最后减速到起始时刻。学习完整时钟重映射，不能仅倒相机而让粒子、文字或拍点仍读片尾时间。

已有 plates 是静态资产，场景修改后需要重建；首尾闭环还要检查编码后的末帧/首帧和音轨，源码 tau→0 不能证明全部输出天然无缝。

## 从这些案例得出的可执行选择

在自己的分镜中优先选择一个当前问题：**看不清作用**用侧面/低位；**不知道整体是什么**用局部→拉远；**动作没有力道**检查跟随是否完全抵消；**镜头晃而没重点**减少同时变化的通道并安排落点；**文字与场景争位置**让机位和 target 为阅读区域让位；**转场后像换了一套东西**查共享状态与出口投影，再按 FrostNova 交接细则验证。

这些是基于案例的选择建议，需由当前歌曲、主体形状和实际画面决定。固定色值、旧歌词、源坐标、角度与时长不作为新 PV 的统一参数。
