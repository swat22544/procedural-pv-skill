## 材料与镜头

定位源音轨、原词、现有对齐与当前输出，读实际入口及写入路径。新歌把音轨、时间表、字体、场景和输出参数放入独立配置，不直接导入会读取旧歌资源的发布脚本。静音机制样片预留事件/音乐接口，标明尚未配真实歌词和音轨。

新方向与新分镜先用 [技巧选用与组合判断](technique-selection.md) 确定本片/章节规则和当前观看任务，写清主导手段、必要辅助与值得排除的候选。下面的专项卡仅在其方法入选时使用，不是每镜都要填写的全套表格；局部小修沿原方案进行。

镜头表记录 id、语义动作、起止事件、主体、景别/视角、相机路径、文字层、切换方式、交接对象和检查时间，只填写对当前镜头有用的字段。需要机位与空间揭示时查 [pdoom-design.md](pdoom-design.md)，每段先用关键帧和短片检查动作成立，再做全片。

需要编排机位变化时使用 [pdoom 导演卡](pdoom-camera-method.md)：说明镜头前后增加的信息、主体屏幕锚点、前景参照、跟随/释放条件、位置/目标/镜头尺度/roll 的分工与阅读区。先判断用三维相机还是平面取景，再做真实时序的低成本预演；大幅运动不能替代明确观察任务。定镜可直接说明其阅读或情绪任务。源码例子见 [逐场拆解](pdoom-shot-cases.md)。

需要前后连贯的镜头，用 [FrostNova 转场与状态接续](frostnova-transitions.md) 的交接单明确：有效 A/B、跨边界时间窗、双方共享的状态/对象映射、最终屏幕锚点、相机与画面/文字分别换手的时刻，以及新阶段动作何时开始。先验同一边界时刻的状态，再看两侧速度和连续片段；不要等整片完成才补转场。

需要元素传递、因果或状态接续时使用 [Misaka 接力契约](misaka-motion-method.md)：写明来源、因果、映射、绘制接管、落点、持久结果和后续动作。检查实际最后一个元素的到达与退场，而非只检查中央元素；共享歌曲时间与场景延迟分别记录。双画面先定义动作/解释/反差的关系，再排主次和阅读时段；不要求普通装饰律动也套载体协议。具体形变、改写、光标、记忆、擦除案例见 [逐链拆解](misaka-motion-cases.md)。

歌词在分镜阶段使用 [歌词分镜卡](lyric-dramaturgy.md)，记录当前需要的声音身份、完整唱词载体、强调词、辅助文本、依附模型、出现/完成/读窗/退场时刻，以及文字动作的可见后果。空间与材料文字入选时查 [pdoom 案例](pdoom-lyric-cases.md)，发言、内心插镜、重复与状态变化入选时查 [Nyanko 案例](nyanko-lyric-cases.md)；稳定字幕也是有效选项。不要到最终合成阶段才决定字幕位置。先检查最长句、最后词，以及本片确有采用的关键词独镜和跨镜交接。

## 音轨与对齐

1. 确认音轨版本、采样率、声道、前奏与尾音，用 SHA256 标识源；片头偏移与歌曲时钟分开。
2. 从用户原词建立行和词；人声分离只供分析，没有分轨时不把混音频带称为真实声源。
3. 歌词约束声学对齐产生候选，再用另一模型/CTC、谱图、RMS/起音交叉核查困难段。本地入口见工具表，不照搬 pdoom 的 macOS MLX 流程。
4. 分开 event_id、source_line_index 和文本；复唱、回声、呼应可共享原词但有不同时间和重叠关系。日文短语内字符插值只能称为视觉插值。
5. 保留零时长词、模型分歧、低音量、重叠、强处理口白等 review flags。启发式 confidence 不是校准概率，器乐里的 ASR 输出不自动成为歌词。
6. 场景切换可吸附节拍，歌词高亮遵循人声；记录吸附容差，不因一个边界调整就整体移动唱词。

特征缓存记录音轨哈希、分析版本、采样率、采样规则和归一化。按视频帧分析时包含 FPS/帧数；如使用 100 Hz 特征，则按绝对时间取样并记录步长。换轨检查/重建，不仅凭 NPZ 存在复用。

## 按镜头选工具

| 镜头需求 | 路线 | 交接 |
|---|---|---|
| 动感文字、DOM/SVG、卡片、轻量 2.5D | Multiplane | SHOT 时间契约、固定舞台、本地资源 |
| Python 数学几何、发光点线 | ModernGL + NumPy，或保留 Pillow 工程 | 绝对时间状态 → 舞台 → 原生文字 → FFmpeg |
| GPU 批量线、SDF、复杂网页多 pass | Three.js/WebGL2 | 证明纯时间 API 后适配 Multiplane，或保留已验证专用导出 |
| 实体遮挡、材质、照明、复杂三维 | Blender MCP + bpy / 原生渲染 | .blend 与 PNG/EXR 序列/透明层 |
| 数学推导、公式变换 | Manim / MathTypst | 独立片段或素材 |
| 已有 AE 工程、原生后效 | AE MCP / JSX + aerender | 原生工程沿对应链路 |
| 拼接、混音、编码、检测 | FFmpeg / FFprobe | 时间基、颜色、音轨和流映射 |

交接契约包含尺寸、FPS、半开帧区间 [first,last)、歌曲时钟原点、颜色空间/范围与 alpha 类型。先验单帧再验短片。透明层必须用支持 alpha 的格式，不透明 H.264 不能代替。

## Multiplane 流程

读取当前安装的 `multiplane` skill 与适用平台说明，保留项目工作目录。以下为 PowerShell 占位示例；先将 `<MULTIPLANE_BIN>` 换成真实启动器路径。npm 路线用 `npx multiplane` 替代前面的 `& '<MULTIPLANE_BIN>'`，见 [环境接入](environment-setup.md)：

```powershell
& '<MULTIPLANE_BIN>' doctor --json
& '<MULTIPLANE_BIN>' lint 'shot.html' --json
& '<MULTIPLANE_BIN>' stills 'shot.html' --at '0,1' --json
& '<MULTIPLANE_BIN>' verify 'shot.html' --workers 1 --json
& '<MULTIPLANE_BIN>' render 'shot.html' --workers 1 --out 'out/preview.mp4' --json
```

时间点必须在当前镜头范围。verify 失败先修复；允许的 GPU raster jitter 警告不等于不确定性失败。setup/ready 完成资源加载，render(t) 同步作画；cuts 声明全部硬切，快门不跨切点。pdoom 内层采样与 Multiplane 外层采样只能明确选一层，避免平方级开销与双重模糊。

PowerShell 调用 .ps1 入口时，逗号列表须作为单个字符串传递（如 --at '0,1'）；未加引号会拆成多个参数，本次微型环境检查已复现 invalid_option，不能直接复制 shell 无关的裸逗号示例。

复杂引擎需要异步 readback、独立采样或状态重放时先证明适配兼容。保留原生/专用导出链是可用选择，不为统一工具破坏已有工程。

## 长片、版本与检查

冻结输入及 HMR；先测最复杂/文字最密镜头的耗时、显存、内存与编码速度，再增加 worker，不把作者 M5 Pro 数据当本机预估。

流式编码或受控分块。新续渲签名覆盖源码、资源、字体、音轨、时序/特征、尺寸、FPS、渲染器、后期/采样和编码配置。旧 world 的 signature 仅覆盖根目录 Python，不称为完备实现。按帧编号重排输出；RAM 与磁盘 spool 有上限。Multiplane 中断先读 job 状态，满足条件再 resume。

验收分别记录：
- 环境：入口、依赖、上下文和工具连接。
- 机制：有限几何、计数/删除状态、字幕完整、乱序确定性和边界。
- 视觉：静帧构图/字形、连续片段运动/转场，包含入点和出点。
- 媒体：关闭文件后 ffprobe、完整 FFmpeg 解码、实际帧数/时长/颜色/音轨；明确偏移与采样率下比较波形。
- 听校：逐句起点、复唱和呼应。自动一致性不能写成人工听校。

检查 console/pageerror 与场景错误占位：参考引擎可能捕获异常后画红底/错误文字继续导出，编码成功不等于场景成功。快速明暗/故障镜头可做亮度、单帧突跳筛查；近似筛查不是医学安全认证。

按新版本输出视频、预览、源码依赖及 manifest，保留署名/资产许可。MIT 代码许可不自动覆盖歌曲、歌词、字体和角色素材。
