# 程序化音乐 PV

把音乐结构、歌词动作和视觉母题编排成有景别、视角、停顿和推进的镜头。保留用户已有工程与美术方向；选择渲染器服务镜头，不为使用工具而迁移整片。新歌不默认继承旧歌的终端、心形、AI 主题、秒数或帧率。

这是设计与生产指导，不是自带渲染器的一键生成程序。参考方法帮助降低起步门槛；每个镜头的表达、故事与最终取舍仍需创作者反复打磨。新环境首次实际制作前读 [环境接入](references/environment-setup.md)，确认渲染器、资源与输出位置；本地案例的历史路径、偏好、验证和权限不自动适用于当前用户。

## 先选用，再查技巧

新建视觉方向、编排或大改分镜时，先读 [技巧选用与组合判断](references/technique-selection.md)，再按下表加载入选方法。局部改字、换音轨、转码或已有明确方案的小修沿原设计处理，不重新开展整片选型。

- 从本曲情绪、歌词/器乐事件和观众此刻的观看任务选方法。四个参考提供可迁移的方法与案例，不是每片必须完成的四项配额，也不要求四选一。
- 先确定本片或有意区分的章节的视觉规则，再借用其他参考的方法。学习机位、时间连续性或动作因果，不自动带入纸色线框、聊天窗、终端、故障等外观。
- 每镜简记“需要看懂/感受到什么 → 主导手段及理由 → 不采用的显眼候选及理由 → 阅读/动作落点”。只记录影响决定的内容；重复镜头可共享规则。
- 默认给同一时刻一个明确的注意力中心；相机、文字、主体与后期可共同工作，关键是同一意图、主次和时间安排，而不是限制只能用一个技巧。密集高潮与抽象节奏都可成立，不强制极简或逐物解释。
- 依据成立才增加复杂度：转场无承接依据可硬切；长句缺乏可读角度可用稳定文字；没有空间信息增益可用平面构图或定镜。用户指定混合风格时保留该方向，规划章节边界和识别线索。
- 短片复核时做删减比较：去掉某层后，情绪、理解、节奏或承接是否受损？无贡献或相互争夺注意力的效果应删除、错开或降低强度。必要的时钟、字体、确定性和导出检查仍执行。

- **细化机位与观看任务、跟拍/揭露/急停、歌词融景**：读 [pdoom 镜头制作细则](references/pdoom-camera-method.md)，按需查 [逐场镜头拆解](references/pdoom-shot-cases.md)。先写观众在镜头前后多看懂了什么，再确定屏幕构图、跟随/停止追踪规则、各相机参数的职责和阅读落点；辨认真实三维相机、二维取景与屏幕后期。

- **元素之间的运动叙事、载体接力、双画面因果、界面剥离与记忆回收**：读 [Misaka 元素连续叙事](references/misaka-motion-method.md) 与 [画面/源码逐链案例](references/misaka-motion-cases.md)。明确源物、发起动作、映射、落地状态和下游动作；区分稳定身份、共享几何、形态匹配与语义呼应，核对最终补丁及绘制责任。

## 先导演，后实现

以“音乐/歌词触发 → 主体动作 → 观众此刻需要看见什么 → 景别和视角 → 下一镜承接物”设计段落。明确本镜改变哪个状态、何时完成、停留多久，以及出镜时交出什么。

参考 pdoom 的关键做法：同一场景可以包含多个相机机位；正面解释结构、斜视揭示体积、低机位强化压迫、贴近局部表现动作、拉远揭示全貌。相机位置、注视点、视场角和滚转分别编排。运动应围绕可追踪主体，不能把全片变成匀速绕转。

每次变机位明确观察任务、主体入画位置、追踪何时开始/结束、动作到达后留下的阅读时间。先确定起终构图，再设计路径；目标可先于位置回应、相机可有限迟后或冻结旧锚点，以显示动作与环境的关系。世界文字和屏幕标签各自决定可读角度、遮挡与留白；不要将所有相机参数同时套同一曲线。

有意硬切、短促换机位、匹配剪辑、连续穿入和形态接续都可成立。按音乐和空间关系选用；不能要求全片一镜到底，也不能用全屏淡化掩盖本应连续的跳变。设计有意义的停顿、加速和落点，歌词阅读区随镜头计划一起确定。

连续性逐项约定：前镜交出的主体、屏幕锚点、形态/相位、相机与速度，由后镜在同一歌曲时间接住；新阶段动作在约定落点后启动。区分边界值相接（C0）、速度也相接（C1）和有意切换。相机运动、场景混合、文字责任与后期变化可使用不同时间窗，不能只加一个全屏转场遮住状态重置。

元素接力还应形成可读的动作后果：前镜的具体对象成为载体，到达后改变后镜的可见状态，再触发下一动作。转场临时接管时隐藏重复副本，交回后由接收场保留到达结果；多对一聚合、区域采样与淡交不要称为身份守恒。逐项检查歌曲钟/场景延迟、最晚错峰元素与相邻窗口优先级；重复道具或操作可通过改变发起者、权力关系和结果推进叙事。

歌词可以是场景里的路标、曲线、纸面、建筑表面或被操作的对象，也可以是稳定字幕。先确定其角色，再做字体与合成。曲面/世界文字需要可读角度、遮挡安排和完整显示时间；稳定字幕在光效之后合成。

歌词与美术共用的不只是配色，还包括字体身份、材料、结构和动作规则。用“说话者/意图 → 文字载体 → 动作 → 可见后果 → 下一镜”编排；可让消息成为内心版画、句子成为文件或路径、关键词成为完整分镜。插镜返回时延续整段时间与消息状态；复唱保留母题但改变结果。全文已生成不等于已读清，要给画内、可辨、可追踪的完成后读窗；复杂画面中保留稳定唱词也是有效选择。

## 制作约定

- 新浏览器镜头以绝对时间 `render(t)` 为核心，初始化加载资源，画面不依赖墙钟或调用历史。固定随机种子、对象 ID、出生时刻；有状态模拟先固定步长烘焙或隔离到明确的顺序渲染链。
- 分开歌曲时间、发布片头偏移、镜头局部时间、连续节拍和离散歌词事件。音乐包络只驱动有界响应，不用 `t * instantaneous_RMS` 当位置时钟。复唱可以重复文字而继续成熟视觉状态。
- 近面裁剪、深度和可见范围在透视除法前后正确处理。已有发光点线渲染器不等于实体遮挡/PBR 引擎。
- 逐字/逐词进度按目标 FPS 调度，完整字符、持留、重叠和光标使用同一布局数据。每帧一字是可选风格；时间不足时按当前项目明确容量，不能漏字。
- 分析人声分轨用于对齐和特征，成片使用用户选定音轨。换歌或换混音时重建时间轴与缓存；保留低置信和人工听校状态。
- 明确计算值、艺术编舞和隐喻：toy 注意力、概率、奖励和优化分别表述，不把编排数值写成实际大模型训练记录。
- 逻辑尺寸与物理像素分离，所有清晰层在目标分辨率生成。HDR、简单柔光、时间采样和后期残影分别命名。
- HTML/CSS/SVG/Canvas/Three.js 新镜头默认配合已安装的 `multiplane` 技能，执行 lint → stills → verify → render；缺少环境时按环境接入页核对并报告具体缺项，不假装已渲染。用户指定导出链、已有专用导出器、Blender/AE 原生工程保持适合的链路，整片可组合输出。不要双重时间采样或重复套后期。
- 先核对入口和当前环境，按新版本输出，保留已交付工程。分段续渲验证输入签名、帧区间、参数和完整性；制作中冻结输入及热更新。

## 复核与交付

关键镜头先看构图静帧，再看含入点、动作落点和出点的连续片段。连续接续比较同一主体在屏幕上的位置、尺度、朝向和速度；硬切检查音乐落点、视线转移与可读性。运动模糊不能代替正确路径。

检查实际生效的镜头与连接，而不只检查配置名；确认不存在关闭镜头误配、缺相机退成硬切或转场窗口意外重叠。接点检查覆盖前镜准备、完整交接和后镜落稳，使用包含父变换、投影偏移与后期缩放的最终屏幕状态，逐项报告覆盖与缺失。

完整导出后核对实际媒体的尺寸、FPS、帧数、音轨、时间偏移和完整解码，再抽编码后关键帧并检查连续片段。歌词调度通过、音频相关性高、确定性抽样通过都不能替代逐句听校或完整视觉验收。

交付视频/预览、可编辑来源与必要依赖、准确的验证范围。技能更新或源码研究不自动授权重渲染旧成片、发布、付费素材生成或修改全机工具配置。学习方法和项目特例分别维护。
